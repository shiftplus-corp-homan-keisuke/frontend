## 🎯 SQL問題攻略法

### 頻出SQL パターン

#### 1. 複雑な結合問題
```sql
-- 典型例：従業員、部署、プロジェクトの3テーブル結合
SELECT e.CONCAT(first_name, ' ', last_name) as employee_name, d.department_name, p.project_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id
LEFT JOIN project_assignments pa ON e.employee_id = pa.employee_id
LEFT JOIN projects p ON pa.project_id = p.project_id
WHERE d.location = '東京'
ORDER BY e.CONCAT(first_name, ' ', last_name) as employee_name;
```

**攻略ポイント**:
- 結合条件を正確に把握
- 内部結合と外部結合の使い分け
- 結合順序によるパフォーマンス影響

#### 2. 相関サブクエリ問題
```sql
-- 典型例：各部署の最高給与者を抽出
SELECT CONCAT(first_name, ' ', last_name) as employee_name, department_id, salary
FROM employees e1
WHERE salary = (
    SELECT MAX(salary)
    FROM employees e2
    WHERE e2.department_id = e1.department_id
);
```

**攻略ポイント**:
- 外側クエリと内側クエリの関係を理解
- EXISTS、NOT EXISTSの使い分け
- パフォーマンスを考慮した書き換え

#### 3. ウィンドウ関数問題
```sql
-- 典型例：部署別売上ランキング
SELECT 
    CONCAT(first_name, ' ', last_name) as employee_name,
    department_id,
    sales_amount,
    RANK() OVER (PARTITION BY department_id ORDER BY sales_amount DESC) as rank
FROM sales_data
WHERE sales_date BETWEEN '2022-01-01' AND '2022-12-31';
```

**攻略ポイント**:
- PARTITION BYとORDER BYの理解
- RANK、DENSE_RANK、ROW_NUMBERの違い
- フレーム句（ROWS、RANGE）の使い方

#### 4. 集約・グループ化問題
```sql
-- 典型例：月別売上集計とその前月比
WITH monthly_sales AS (
    SELECT 
        DATE_FORMAT(sale_date, '%Y-%m') as month,
        SUM(sales_amount) as total_sales
    FROM sales
    GROUP BY DATE_FORMAT(sale_date, '%Y-%m')
)
SELECT 
    month,
    total_sales,
    LAG(total_sales) OVER (ORDER BY month) as prev_month_sales,
    ROUND((total_sales - LAG(total_sales) OVER (ORDER BY month)) / 
          LAG(total_sales) OVER (ORDER BY month) * 100, 2) as growth_rate
FROM monthly_sales;
```

**攻略ポイント**:
- GROUP BY句の制限事項
- HAVINGとWHEREの使い分け
- CTEの効果的な活用

### SQL問題の解答手順

1. **要件の整理**
   - 何を求められているかを明確化
   - 必要なテーブルと列を特定
   - 条件を整理

2. **テーブル関係の把握**
   - ER図や制約から関係を理解
   - 結合キーを特定
   - カーディナリティを考慮

3. **段階的な構築**
   - 単純なクエリから開始
   - 段階的に条件や結合を追加
   - 中間結果を確認

4. **最適化の検討**
   - インデックスの効果
   - 結合順序の最適化
   - サブクエリの書き換え

## 📊 データベース設計問題攻略法

### ER図作成のポイント

#### 1. エンティティの抽出
- **名詞に注目**: 要件文から重要な名詞を抽出
- **独立性の確認**: 他のエンティティに依存しない概念
- **属性との区別**: エンティティか属性かの判断

#### 2. 関係の設定
- **カーディナリティ**: 1:1、1:N、M:Nの判断
- **参加制約**: 全参加（必須）か部分参加（任意）か
- **依存関係**: 強エンティティと弱エンティティ

#### 3. 属性の設定
- **主キー**: エンティティを一意に識別
- **外部キー**: 他のエンティティとの関係
- **導出属性**: 他の属性から計算可能

### 正規化問題のポイント

#### 第1正規形（1NF）
- **原子値**: 各属性が分割不可能な値
- **繰り返しグループの排除**: 配列や複数値の分離

#### 第2正規形（2NF）
- **部分関数従属の排除**: 主キーの一部に従属する属性を分離
- **複合主キー**: 特に注意が必要

#### 第3正規形（3NF）
- **推移関数従属の排除**: 主キー以外の属性に従属する属性を分離
- **間接的な依存関係**: A→B→Cの関係を分離

#### ボイス・コッド正規形（BCNF）
- **決定子**: 全ての決定子が候補キー
- **3NFでも問題となるケース**: 複数の候補キーが存在する場合

### 正規化の判断基準

**正規化を進める場合**:
- データの整合性が重要
- 更新異常を防ぎたい
- ストレージ容量を節約したい

**非正規化を検討する場合**:
- 検索性能が重要
- 結合コストが高い
- 読み取り専用のデータ

## 🎯 頻出キーワード・概念

### データベース基礎
- **ACID特性**: 原子性、一貫性、独立性、永続性
- **正規化**: 1NF、2NF、3NF、BCNF
- **インデックス**: B-tree、ハッシュ、ビットマップ
- **トランザクション**: コミット、ロールバック、分離レベル

### SQL技術
- **結合**: 内部結合、外部結合、自己結合
- **サブクエリ**: 相関サブクエリ、EXISTS、IN
- **ウィンドウ関数**: RANK、ROW_NUMBER、LAG、LEAD
- **CTE**: 共通テーブル式、再帰クエリ

### システム設計
- **可用性**: レプリケーション、フェイルオーバー
- **拡張性**: パーティショニング、シャーディング
- **性能**: インデックス設計、クエリ最適化
- **セキュリティ**: アクセス制御、暗号化

### 最新技術
- **NoSQL**: ドキュメント型、キー・バリュー型、グラフ型
- **クラウドDB**: AWS RDS、Azure SQL Database
- **ビッグデータ**: Hadoop、Spark、データレイク
- **AI・ML**: 機械学習、データマイニング
