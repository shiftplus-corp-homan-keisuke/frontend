# State vs. Props

非常に一般的な初心者の質問、
あるいは時には面接の質問でもあるのが、
stateとpropsの違いは何ですか？
実際、その質問に答えるために必要なことはほとんどすべて学びましたが、
この講義でstateとpropsの違いを明確にしましょう。
これはこのセクション全体の良いまとめにもなります。
既にご存知のとおり、stateは内部データです。
宣言されているコンポーネントが所有するデータであり、
この2つのコンポーネントの小さな例でそれがよくわかります。
一方、propsは外部データです。
親コンポーネントが所有するデータであり、
propsは関数パラメーターと考えることができます。
つまり、親と子コンポーネント間の通信チャネルであり、親は
データを子に渡すことができます。
stateは、コンポーネントのメモリと考えることができます。
なぜなら、時間とともにデータを保持できるからです。
つまり、複数の再レンダリングをまたいで。
stateはコンポーネント自身によって更新でき、
既に知っているように、これにより
Reactによってコンポーネントが再レンダリングされます。
したがって、このstateのメカニズムを使用して
コンポーネントをインタラクティブにします。
一方、propsは非常に異なる動作をします。
それらは読み取り専用であり、
それらを受け取るコンポーネントによって変更することはできません。
しかし、これは私たちが以前に学んでいないことですが、
子コンポーネントが新しい更新されたpropsを受け取ると、
実際にはコンポーネントも再レンダリングされます。
このコード例で実際にそれを分析してみましょう。
questionに渡されたpropsの1つは「Up Votes」と呼ばれ、
その`upVotes`変数は実際には状態です。
そして、親コンポーネントでは、
`useState`フックを使用して作成されます。
したがって、`upVotes`は実際には状態です。
さて、この状態の一部が更新された場合、もちろん、
状態を所有するquestionコンポーネントは再レンダリングされますが、
その状態をpropsとして受け取る子コンポーネントも再レンダリングされるべきですよね？
そうでなければ、ボタンコンポーネントが
propsとして受け取った状態と同期を保つ方法がありません。
結論として、状態の一部がpropとして渡され、その状態が更新されると、
両方のコンポーネントが再レンダリングされます。
つまり、状態を所有するコンポーネントと、
状態をpropとして受け取るコンポーネントの両方です。
これは、状態とpropの間の非常に重要なつながりであり、
覚えておくべきです。
最後に、状態は開発者によって
コンポーネントをインタラクティブにするために使用されますが、
propsは親コンポーネントに
子コンポーネントを構成する機能を与えるために使用されます。
だから、基本的にpropsは
子コンポーネントの設定と見なすことができます。
親コンポーネントは好きなように定義できます。
これで終わりです。
もし仕事の面接でstateとpropsの違いを尋ねられたら、
きっとうまく答えられることを願っています。

```js
    id: 9103,

    answer: "useStateフック"
  },
  {
    id: 2002,
    question:
      "状態と完全に同期している入力要素を何と呼びますか？",
    answer: "制御された要素"
  }
];

function FlashCards() {
  const [selectedId, setSelectedId] = useState(null);

  function handleClick(id) {
    setSelectedId(id !== selectedId ? id : null);
  }

  return (
    <div className="flashcards">
      {questions.map((question) => (
        <div
          key={question.id}
          onClick={() => handleClick(question.id)}
          className={question.id === selectedId ? "selected" : ""}
        >
          <p>
            {question.id === selectedId ? question.answer : question.question}
          </p>
        </div>
      ))}
    </div>
  );
}
```

```js
import { useState } from "react";

export default function App() {
  return (
    <div className="App">

function Counter() {
  const [count, setCount] = useState(0);
  const [step, setStep] = useState(1);

  function handleReset() {
    setCount(0);
    setStep(1);
  }

  const date = new Date("june 21 2027");
  date.setDate(date.getDate() + count);

  return (
    <div>
      <div>
        <input
          type="range"
          min="0"
          max="10"
          value={step}
          onChange={(e) => setStep(Number(e.target.value))}
        />
        <span>Step: {step}</span>
      </div>

      <div>
        <button onClick={() => setCount((c) => c - step)}>-</button>
        <input
          type="text"
          value={count}
          onChange={(e) => setCount(Number(e.target.value))}
        />
        <button onClick={() => setCount((c) => c + step)}>+</button>
      </div>

      <p>
        <span>
          {count === 0
            ? "Today is "
            : count > 0
            ? `${count} days from today is `
            : `${Math.abs(count)} days ago was `}
        </span>
        <span>{date.toDateString()}</span>
      </p>

      {count !== 0 || step !== 1 ? (
        <div>
          <button onClick={handleReset}>Reset</button>
        </div>
      ) : null}
    </div>
  );
}
```

# 状態管理の基本

以前に、状態がReactで最も重要な概念であることを学びました。
したがって、状態管理はReactで考える上で最も重要な側面です。
それでは、Reactにおける状態管理の基本について話しましょう。
既にご存知のとおり、useState関数を使用して、
アプリケーションのライフサイクル中に変化するデータを追跡するために、
複数の状態を作成できます。
Udemyアプリケーションには、状態の多くの例があります。
ご存知の通りです。
もしよろしければ、ビデオを一時停止して、
これをすぐに分析してみてください。
さて、これらすべては少し混乱しているように見えますね？
これらすべての状態が本当に必要なのか、
どうやってわかるのでしょうか？
そして、それらをコード内のどこに正確に配置するのか、
どうやってわかるのでしょうか？
そこで状態管理が登場します。
状態管理は、人によってさまざまな方法で定義できます。
しかし、私は状態管理を、
いつ新しい状態を作成する必要があるか、
どのような種類の状態が必要か、
各状態をコードベース内のどこに配置するか、
そして、すべてのデータがアプリ内でどのように流れるべきかを決定することと捉えるのが好きです。
これらをすべてまとめると、
私は状態管理を、基本的に各状態に
コードベース内で「家」を与えることと例えるのが好きです。
さて、今のところ、私たちの小さなアプリでは、
状態管理についてまったく心配する必要はありませんでした。
各状態を必要とするコンポーネントに配置するだけで、それで終わりでした。
しかし、アプリケーションが成長するにつれて、各状態に適切な「家」を見つける必要性が
本当に重要になり始めます。
その「家」が、最初にその状態を必要とするコンポーネントであろうと、
いくつかの親コンポーネントであろうと、あるいはグローバル状態であろうと関係なく。
グローバル状態といえば、
Reactに存在する2つの大きな種類の状態、
グローバル状態とローカル状態の違いを実際に分析しましょう。
さて、これは後になってから私たちにとってより重要になるだけですが、
この「状態について考える」セクションで、
これについて学び始めましょう。
だから、Reactでは、各状態は
ローカル状態かグローバル状態のどちらかです。
だから、ローカル状態は、1つのコンポーネント、
またはいくつかの子コンポーネントや兄弟コンポーネントなど、
ごく少数の異なるコンポーネントでのみ必要とされる状態です。
useState関数を特定のコンポーネント内で使用して、
単にローカル状態を作成します。
そして、その状態は、そのコンポーネントと、
propsを使用して状態を渡せば、その子コンポーネントにのみアクセス可能です。
Udemyアプリに戻ると、
ローカル状態の例は、検索バーの入力テキストかもしれません。
だから、おそらくそのコンポーネントだけが
このデータについて知る必要があります。
したがって、これはローカル状態です。
つまり、その検索バーコンポーネントにローカルな状態です。
さて、グローバル状態については、
これはアプリ内の多くの異なるコンポーネントがアクセスする必要がある状態です。
したがって、状態をグローバルとして定義すると、
その状態はアプリ全体のすべてのコンポーネントからアクセス可能になります。
すべてのコンポーネント間で共有されるため、
共有状態と呼ぶこともできます。
実際には、ReactのContext APIを使用するか、
Reduxのような外部のグローバル状態管理ライブラリを使用して、
グローバル状態を定義できます。
Reduxについては聞いたことがあるかもしれません。
さて、このUdemyアプリでは、
グローバル状態の一部はショッピングカートです。
だから、そのデータはあちこちで使われています。
だから、これらのすべてのコンポーネントは
ショッピングカートの状態にアクセスする必要があります。
したがって、これがグローバル状態であることは理にかなっています。
さて、ローカル状態とグローバル状態のこの区別は、大規模なアプリケーションでより重要になります。

# 派生状態（Derived State）

私が状態管理の講義で述べたもう一つの側面は、
派生状態（derived state）でした。
複雑に聞こえるかもしれませんが、実際には非常に簡単です。
簡単に言えば、派生状態とは、
既存の他の状態、またはプロップから計算された状態のことです。
しかし、実際のコードを見てみましょう。
ここでは、`useState`関数の呼び出しが3回あることからわかるように、
3つの状態があります。
しかし、これらの状態を分析すると、
すべてが存在する意味はあまりありません。
なぜなら、`numItems`と`totalPrice`は完全に`cart`に依存しているからです。
`numItems`は単にカート内のアイテム数であり、
`totalPrice`はカート内のすべての価格の合計です。
したがって、これらの2つの状態に必要なデータは、
実際にはすでにカートに存在しており、
これらの追加の状態変数を作成する必要はありません。
そうすることは実際にはかなり問題があります。
まず、これらすべての状態を同期させておく必要があるからです。
したがって、常に一緒に更新するように注意する必要があります。
この状況では、カートを更新するたびに、
アイテム数と合計価格も手動で更新する必要があり、
そうしないと、状態が同期しなくなります。
しかし、これらの3つの状態を個別に更新すると、
2番目の問題が発生します。
なぜなら、この例では絶対に不必要なのに、
コンポーネントが3回再レンダリングされてしまうからです。
代わりに、`numItems`と`totalPrice`の状態を`cart`から派生させるだけで、
これらすべての問題を解決できます。
なぜなら、`cart`にはすでに必要なすべてのデータが含まれているからです。
だから、ここでは、`numItems`を単にカートの長さとして計算し、
`totalPrice`をすべての価格の合計として計算し、
それらを通常の変数に格納します。

```js
          curOpen={curOpen}

function AccordionItem({ num, title, curOpen, onOpen, children }) {
  const isOpen = num === curOpen;

  function handleToggle() {
    onOpen(isOpen ? null : num);
  }

  return (
    <div className={`item ${isOpen ? "open" : ""}`} onClick={handleToggle}>
      <p className="number">{num < 9 ? `0${num + 1}` : num + 1}</p>
      <p className="title">{title}</p>
      <p className="icon">{isOpen ? "-" : "+"}</p>

      {isOpen && <div className="content-box">{children}</div>}
    </div>
  );
}
```

`app.js`

```js
import "./styles.css";
import { useState } from "react";

export default function App() {
  return (
    <div>
      <TipCalculator />
    </div>
  );
}

function TipCalculator() {
  const [bill, setBill] = useState("");
  const [percentage1, setPercentage1] = useState(0);
  const [percentage2, setPercentage2] = useState(0);

  const tip = bill * ((percentage1 + percentage2) / 2 / 100);

  function handleReset() {
    setBill("");
    setPercentage1(0);
    setPercentage2(0);
  }

  return (
    <div>
      <BillInput bill={bill} onSetBill={setBill} />
      <SelectPercentage percentage={percentage1} onSelect={setPercentage1}>
        サービスはいかがでしたか？
      </SelectPercentage>
      <SelectPercentage percentage={percentage2} onSelect={setPercentage2}>
       ご友人のサービスの評価はいかがでしたか？
      </SelectPercentage>

      {bill > 0 && (
        <>
          <Output bill={bill} tip={tip} />
          <Reset onReset={handleReset} />
        </>
      )}
    </div>
  );
}

function BillInput({ bill, onSetBill }) {
  return (
    <div>
      <label>お会計はいくらでしたか?</label>
      <input
        type="text"
        placeholder="Bill value"
        value={bill}
        onChange={(e) => onSetBill(Number(e.target.value))}
      />
    </div>
  );
}

function SelectPercentage({ children, percentage, onSelect }) {
  return (
    <div>
      <label>{children}</label>
      <select
        value={percentage}
        onChange={(e) => onSelect(Number(e.target.value))}
      >
        <option value="0">不満 (0%)</option>
        <option value="5">普通 (5%)</option>
        <option value="10">良かった (10%)</option>
        <option value="20">とても良かった (20%)</option>
      </select>
    </div>
  );
}

function Output({ bill, tip }) {
  return (
    <h3>
      You pay ${bill + tip} (${bill} + ${tip} tip)
    </h3>
  );
}

function Reset({ onReset }) {
  return <button onClick={onReset}>Reset</button>;
}
```
