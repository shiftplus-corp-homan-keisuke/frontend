# 直交性 (Orthogonality) in Angular

## 概念: 直交性とは？
『達人プログラマー』における直交性とは、「**ある部分を変更しても、他の部分に影響を与えないこと**」を意味します。
直交性が高いシステムは、メンテナンスが容易で健全です。逆に直交性が低い（結合度が高い）システムは、一箇所の修正が予期せぬバグを引き起こす悪夢のような状態になります。

Angular 開発において、直交性を高めるための主要なアプローチは以下の2つです：

1. **Smart/Dumb Component パターン (Container/Presentation パターン)**
2. **Dependency Injection (依存性の注入) によるサービスの分離**

---

## 1. Smart vs Dumb Components

コンポーネントの役割を明確に分離することで、UIの変更がビジネスロジックに影響せず、逆にロジックの変更がUIの実装詳細に影響しないようにします。

### Dumb Component (Presentation Component)
- **役割**: データの表示とユーザーイベントの伝達のみ。
- **特徴**:
  - `Service` を注入しない（依存を持たない）。
  - `@Input()` でデータを受け取り、`@Output()` でイベントを親に通知する。
  - 純粋な関数のように、入力が決まれば出力（見た目）が決まる。
  - **直交性のメリット**: どこでも再利用可能。ビジネスロジックが変わっても、このコンポーネントを変更する必要がない。

### Smart Component (Container Component)
- **役割**: データの取得、更新、ビジネスロジックの実行。
- **特徴**:
  - `Service` を利用してデータストアやAPIと通信する。
  - Dumb Component を配置し、必要なデータを渡し、イベントをハンドリングする。
  - 具体的な HTML マークアップや CSS は最小限（構造定義のみ）。
  - **直交性のメリット**: UI の見た目（Dumb Component）を変更しても、データ取得ロジック（Smart Component）には影響しない。

## 2. Dependency Injection (DI)

具体的なクラスではなく、抽象（Service）に依存させることで、実装を切り離します。
コンポーネントは「データが欲しい」とだけ宣言し、「どうやってデータを取るか（HTTP, LocalStorage, Mock）」を知る必要がありません。これにより、コンポーネントとデータソースが**直交**します。
