# Session1: React開発環境とコンポーネント基礎

## 🎯 このセッションで学ぶこと

このセッションでは、Reactアプリケーション構築の3つの核となる概念を探求します：

- **コンポーネント**：Reactアプリケーションの構成要素
- **Props**：コンポーネント間でのデータ共有
- **JSX**：強力な宣言的構文

これらすべてを、美しい最初のプロジェクトを構築しながら実践していきます。

学習の過程で、これらの基本的なスキルを使用して開発者プロフィールカードを構築することで、Reactの実践的な練習も行います。

## 🚀 ルートコンポーネントのレンダリングとStrictMode

### プロジェクトの初期設定

ピザメニュープロジェクトの構築を完全にゼロから始めましょう。

まず、不要なファイルをすべて削除し、プロジェクトを一から作成します。ブラウザを右側に、コードエディタを左側に配置して、常に出力を確認できるようにしましょう。

### React 18での基本セットアップ

最初のファイル `index.js` を作成します。このファイル名は重要です。なぜなら、webpack（このプロジェクトのモジュールバンドラー）は、エントリーポイントが `index.js` という名前であることを期待しているからです。

```javascript
// 基本的なReactライブラリのインポート
import React from 'react';
import ReactDOM from 'react-dom/client';
```

これらは単純なJavaScriptのモジュールインポートです。ES6以降のJavaScriptの機能を使用しています。

### Appコンポーネントの作成

```javascript
function App() {
  return <h1>Hello React!</h1>;
}
```

**重要なルール**：
- コンポーネント名は**大文字で始める**必要があります
- 関数は何らかのマークアップ（通常はJSX）を返す必要があります

### React 18でのレンダリング方法

```javascript
// React 18の新しいレンダリング方法
const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(<App />);
```

この方法は、public/index.htmlファイル内の `id="root"` を持つdiv要素を選択し、そこにReactアプリケーションをレンダリングします。

### React 17以前との違い

参考として、React 17以前では以下のような書き方でした：

```javascript
// React 17以前の方法（参考用）
// ReactDOM.render(<App />, document.getElementById('root'));
```

### StrictModeの活用

```javascript
const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
```

**StrictModeの効果**：
- 開発中にすべてのコンポーネントを2回レンダリングしてバグを発見
- 古いReact APIの使用をチェック
- 開発時のみ動作（本番環境では影響なし）

StrictModeは画期的な機能ではありませんが、Reactアプリケーション開発時には常に有効にすることをお勧めします。

### よくある問題と解決方法

これから自分のコンピューターでコーディングを始めると、エラーが発生することは避けられません。そこで、これらの問題に対処するためのテクニックをご紹介します。

#### 1. アプリケーションが更新されない場合

**解決手順**：

1. **アプリが実際に動作しているか確認**
   ```bash
   npm start
   ```

2. **アプリの停止と再起動**
   - `Ctrl + C`（Mac/Windows共通）でアプリを停止
   - 再度 `npm start` で起動

3. **ブラウザのハードリロード**
   - リロードボタンをクリック
   - ホットモジュールリプレースメントが時々失敗するため

#### 2. 開発環境の設定

**常に開いておくべきもの**：
- **ターミナル**：アプリの実行状態を確認
- **ブラウザの開発者ツール**：コンソールでエラーを確認

```javascript
// 開発者ツールのコンソールを開く方法
// F12キーまたは右クリック → 検証
```

#### 3. エラーメッセージの活用

Create React Appは、エラーが発生すると画面上にオーバーレイを表示します：

```javascript
// 意図的にエラーを発生させる例
function App() {
  return (
    <h1>Hello React!</h1>
    <p>これはエラーになります</p> // 隣接するJSX要素はラップが必要

```

**エラーメッセージの読み方**：
- 最初の部分は通常重要ではない
- 具体的なエラー内容に注目
- 分からない場合はGoogleで検索


**ESLintの利点**：
- 未使用変数の検出
- コーディング規約の強制
- 潜在的な問題の早期発見

#### 5. VS Codeの問題タブ

- **Problems**タブで警告やエラーを確認
- **Output**タブでPrettierやESLintの状態を確認

#### 6. 最終手段：完成コードとの比較

問題が解決しない場合は、提供された完成コードと比較して違いを見つけましょう。

## 🧱 コンポーネント：構成要素としての概念

### コンポーネントとは何か

**コンポーネントはReactの最も基本的な概念**です。なぜなら、Reactアプリケーションは完全にコンポーネントで構成されているからです。

Reactアプリを見ると、コンポーネントでないものや、少なくとも何らかのコンポーネントの内部にないものは存在しません。

### コンポーネントの特徴

コンポーネントは**ユーザーインターフェースの構成要素**です：

- **独自のデータ**を持つ
- **JavaScriptロジック**を含む
- **外観**を定義する

基本的に、各コンポーネントは自分がどのように動作し、どのように見えるかを記述します。

### 複雑なUIの構築方法

```
複雑なUI = 複数のコンポーネント + レゴのような組み合わせ
```

例：Airbnbのようなアプリケーション
- **ビデオプレーヤー**コンポーネント
- **メニュー**コンポーネント
- **質問リスト**コンポーネント
- **質問絞り込み**コンポーネント

### コンポーネントの入れ子構造

```jsx
// 親コンポーネント内に子コンポーネントを配置
function RefinedQuestions() {
  return (
    <div>
      <Filter /> {/* 子コンポーネント */}
      <QuestionList />
    </div>
  );
}
```

### コンポーネントの再利用性

同じコンポーネントを異なるデータで複数回使用：

```jsx
// 同じQuestionコンポーネントを3回再利用
<QuestionList>
  <Question data={question1} />
  <Question data={question2} />
  <Question data={question3} />
</QuestionList>
```

重複が必要な場合は、新しいコンポーネントを作成し、必要な回数だけ使用します。

### コンポーネントツリー

コンポーネント間の階層関係を理解するために、**コンポーネントツリー**を使用します：

```
App
├── VideoPlayer
├── Menu
├── RefinedQuestions
│   └── Filter
└── QuestionList
    ├── Question
    ├── Question
    └── Question
```

**用語**：
- **親コンポーネント**：他のコンポーネントを含むコンポーネント
- **子コンポーネント**：他のコンポーネント内に含まれるコンポーネント

これらの用語はReactで頻繁に使用されるため、理解しておくことが重要です。

## ♻️ コンポーネントの作成と再利用

### スターターファイルの準備

プロジェクトを続ける前に、GitHubからダウンロードしたスターターファイルを取得しましょう：

**必要なファイル**：
- `pizzas/`フォルダ（画像ファイル）
- `data.js`（ピザデータ）
- `index.css`（スタイルファイル）

これらのファイルを適切な場所に配置します：
- 画像フォルダとdata.jsは`public/`フォルダに
- `index.css`は`src/`フォルダに

### 新しいコンポーネントの作成

Reactでは**関数を使用して新しいコンポーネントを作成**します：

```javascript
function Pizza() {
  return <h2>Pizza</h2>;
}
```

**コンポーネント作成の重要なルール**：

1. **関数名は大文字で始める**（例：`Pizza`、`App`）
2. **何らかのマークアップを返す**（JSXまたはnull）

### コンポーネントの使用

```javascript
function App() {
  return (
    <div>
      <h1>Hello React!</h1>
      <Pizza />
    </div>
  );
}
```

**重要な注意点**：
- 各コンポーネントは**1つの要素のみ**を返すことができます
- 複数の要素を返す場合は、`<div>`などでラップする必要があります

### コンポーネントのネスト

```javascript
// ❌ 間違った方法：関数内で関数を定義
function App() {
  function Pizza() { // これは避けるべき
    return <h2>Pizza</h2>;
  }
  return <div><Pizza /></div>;
}

// ✅ 正しい方法：トップレベルで関数を定義
function Pizza() {
  return <h2>Pizza</h2>;
}

function App() {
  return (
    <div>
      <Pizza />
    </div>
  );
}
```

### より興味深いコンポーネントの作成

スターターデータを使用してより実用的なコンポーネントを作成しましょう：

```javascript
// ピザデータ（簡略版）
const pizzaData = [
  {
    name: "スピナーチピザ",
    ingredients: "トマト、モッツァレラ、ほうれん草、リコッタチーズ",
    price: 12,
    photoName: "pizzas/spinaci.jpg",
    soldOut: false,
  },
  // ... 他のピザデータ
];

function Pizza() {
  return (
    <div>
      <img src="pizzas/spinaci.jpg" alt="スピナーチピザ" />
      <h2>スピナーチピザ</h2>
      <p>トマト、モッツァレラ、ほうれん草、リコッタチーズ</p>
    </div>
  );
}
```

### 画像の配置について

**重要**：すべてのアセット（画像など）は`public/`フォルダに配置します。Webpackが自動的にこれらのファイルを処理します。

```javascript
// public/pizzas/spinaci.jpgにアクセス
<img src="pizzas/spinaci.jpg" alt="スピナーチピザ" />
```

### ESLintによる品質管理

```javascript
// ESLintの警告例
<img src="pizzas/spinaci.jpg" /> // 警告: img要素にalt属性がありません

// 修正版
<img src="pizzas/spinaci.jpg" alt="スピナーチピザ" />
```

### コンポーネントの再利用

```javascript
function App() {
  return (
    <div>
      <h1>Hello React!</h1>
      <Pizza />
      <Pizza />
      <Pizza />
    </div>
  );
}
```

現在は同じデータが3回表示されますが、後でpropsを学習すると、各コンポーネントに異なるデータを渡すことができるようになります。

### 開発環境の設定（オプション）

VS Codeでより快適に開発するために、Git関連の表示を無効にすることができます：

1. 設定を開く
2. "diff decorations"を検索
3. "none"に設定

これにより、エディタがよりクリーンに表示されます。

## 🎯 重要なポイント

### React開発の基本原則

- **コンポーネント思考**：UIを小さな再利用可能な部品として考える
- **宣言的アプローチ**：「何を」表示するかに集中する
- **単一責任の原則**：各コンポーネントは1つの明確な役割を持つ

### 開発効率を上げるコツ

- **常にターミナルと開発者ツールを開いておく**
- **ESLintの警告に注意を払う**
- **エラーメッセージを恐れずに読む**
- **小さく始めて段階的に複雑にする**

### よくある間違いと対策

| 間違い | 正しい方法 | 理由 |
|--------|------------|------|
| 小文字でコンポーネント名を開始 | 大文字で開始 | Reactの規約 |
| 複数要素を直接返す | 1つの親要素でラップ | JSXの制限 |
| 関数内で関数を定義 | トップレベルで定義 | パフォーマンスの問題 |

このセッションで学んだ基礎知識は、React開発の土台となります。次のセッションでより高度な概念を学ぶ準備が整いました！
