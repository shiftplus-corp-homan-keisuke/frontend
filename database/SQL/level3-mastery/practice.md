# データベーススペシャリスト試験 SQL学習教材
## Level 3: Mastery（上級レベル）- 練習問題

## 概要

このファイルでは、データベーススペシャリスト試験の上級レベルに対応した実践的な練習問題を提供します。理論学習で習得した知識を実際のSQL文として実装し、実務レベルのスキルを身につけることを目標とします。

## 使用方法

1. **段階的な学習**: セクション1から順番に進めてください
2. **実際の実行**: 可能な限り実際のデータベース環境で実行してください
3. **解答確認**: [`solutions.md`](./solutions.md)で解答と解説を確認してください
4. **反復練習**: 間違えた問題は時間を置いて再度挑戦してください

## 前提条件

- Level 2: Application（中級レベル）の内容を理解していること
- 基本的なウィンドウ関数、外部結合、サブクエリを使用できること
- 実際のデータベース環境（PostgreSQL、MySQL、Oracle等）が利用可能であること

## セクション1: 高度なウィンドウ関数（15問）

### 基本データ
以下のテーブル構造を前提とします：

```sql
-- 売上テーブル
CREATE TABLE sales (
    sale_id SERIAL PRIMARY KEY,
    customer_id INT,
    product_id INT,
    sale_date DATE,
    amount DECIMAL(10,2),
    quantity INT,
    region VARCHAR(50)
);

-- 顧客テーブル
CREATE TABLE customers (
    customer_id SERIAL PRIMARY KEY,
    customer_name VARCHAR(100),
    registration_date DATE,
    customer_type VARCHAR(20) -- 'PREMIUM', 'STANDARD', 'BASIC'
);

-- 商品テーブル
CREATE TABLE products (
    product_id SERIAL PRIMARY KEY,
    product_name VARCHAR(100),
    category VARCHAR(50),
    unit_price DECIMAL(10,2)
);
```

### 問題1-1: LAG関数による前期比較
各顧客の月別売上と前月売上、前月比成長率を求めてください。

**要求事項:**
- 顧客ID、年月、月別売上、前月売上、成長率（%）を表示
- 成長率は小数点以下2桁まで表示
- 前月売上がない場合はNULLを表示

### 問題1-2: LEAD関数による将来予測
各商品の日別売上と翌日売上を比較し、売上が減少する日を特定してください。

**要求事項:**
- 商品ID、売上日、当日売上、翌日売上、減少フラグを表示
- 減少フラグは翌日売上が当日売上より少ない場合に'DOWN'を表示

### 問題1-3: FIRST_VALUE/LAST_VALUE関数
各地域の月別売上において、その月の最初の売上と最後の売上を表示してください。

**要求事項:**
- 地域、年月、最初の売上日、最初の売上額、最後の売上日、最後の売上額を表示
- 日付順でソートして表示

### 問題1-4: NTILE関数による分位数分析
全顧客を年間売上額に基づいて4つのグループ（四分位数）に分け、各グループの統計を求めてください。

**要求事項:**
- 四分位数、顧客数、平均売上額、最小売上額、最大売上額を表示
- 売上額は小数点以下2桁まで表示

### 問題1-5: 移動平均の計算
各商品の日別売上について、7日間の移動平均を計算してください。

**要求事項:**
- 商品ID、売上日、当日売上、7日移動平均を表示
- 移動平均は小数点以下2桁まで表示
- データが7日未満の場合も計算対象とする

### 問題1-6: 累積売上の計算
各顧客の注文日順での累積売上額を計算してください。

**要求事項:**
- 顧客ID、売上日、売上額、累積売上額を表示
- 顧客別、日付順でソート

### 問題1-7: パーセンタイル計算
各カテゴリの商品について、売上額の25%、50%、75%パーセンタイルを求めてください。

**要求事項:**
- カテゴリ、25%パーセンタイル、50%パーセンタイル、75%パーセンタイルを表示

### 問題1-8: ランキング関数の比較
各地域の月別売上について、RANK、DENSE_RANK、ROW_NUMBERの違いを示してください。

**要求事項:**
- 地域、年月、売上額、RANK、DENSE_RANK、ROW_NUMBERを表示
- 売上額の降順でランキング

### 問題1-9: 条件付きウィンドウ関数
各顧客の売上について、20万円以上の売上のみを対象とした累積売上を計算してください。

**要求事項:**
- 顧客ID、売上日、売上額、条件付き累積売上を表示
- 20万円未満の売上は累積に含めない

### 問題1-10: 複数条件でのパーティション
商品カテゴリと地域の組み合わせごとに、月別売上のランキングを求めてください。

**要求事項:**
- カテゴリ、地域、年月、売上額、ランキングを表示
- カテゴリ・地域別にパーティション分割

### 問題1-11: ウィンドウフレームの活用
各商品の売上について、過去3日間と未来3日間（計7日間）の売上平均を計算してください。

**要求事項:**
- 商品ID、売上日、売上額、7日間平均を表示
- ROWS BETWEEN 3 PRECEDING AND 3 FOLLOWINGを使用

### 問題1-12: 比率計算
各顧客の月別売上が、その月の全体売上に占める割合を計算してください。

**要求事項:**
- 顧客ID、年月、売上額、全体に占める割合（%）を表示
- 割合は小数点以下2桁まで表示

### 問題1-13: 最大値・最小値の特定
各地域で最も売上の多い日と少ない日を特定してください。

**要求事項:**
- 地域、最大売上日、最大売上額、最小売上日、最小売上額を表示

### 問題1-14: 連続する期間の分析
各顧客について、連続して売上がある期間の長さを計算してください。

**要求事項:**
- 顧客ID、連続期間の開始日、終了日、期間の長さ（日数）を表示

### 問題1-15: 複雑な条件でのウィンドウ関数
各商品について、売上額が前日比で10%以上増加した日を特定してください。

**要求事項:**
- 商品ID、売上日、売上額、前日売上額、増加率（%）、増加フラグを表示
- 増加率が10%以上の場合に'HIGH_GROWTH'フラグを設定

## セクション2: 再帰クエリ（WITH RECURSIVE）（12問）

### 基本データ
以下のテーブル構造を前提とします：

```sql
-- 組織テーブル
CREATE TABLE departments (
    dept_id SERIAL PRIMARY KEY,
    dept_name VARCHAR(100),
    parent_dept_id INT,
    manager_name VARCHAR(100),
    budget DECIMAL(12,2)
);

-- 従業員テーブル
CREATE TABLE employees (
    employee_id SERIAL PRIMARY KEY,
    employee_name VARCHAR(100),
    dept_id INT,
    manager_id INT,
    salary DECIMAL(10,2),
    hire_date DATE
);

-- カテゴリテーブル（階層構造）
CREATE TABLE categories (
    category_id SERIAL PRIMARY KEY,
    category_name VARCHAR(100),
    parent_category_id INT,
    level INT
);
```

### 問題2-1: 基本的な階層表示
組織の階層構造を表示してください。

**要求事項:**
- 部門ID、部門名、階層レベル、階層パスを表示
- 階層レベルに応じてインデントを付ける
- ルート部門から順番に表示

### 問題2-2: 特定部門の配下組織
指定した部門（例：dept_id = 10）の配下にある全ての部門を表示してください。

**要求事項:**
- 指定部門を含む配下の全部門を表示
- 階層レベルと部門名を表示
- 階層の深さ制限は10レベルまで

### 問題2-3: 従業員の上司階層
指定した従業員（例：employee_id = 100）の上司の階層を表示してください。

**要求事項:**
- 従業員から最上位の上司まで階層を表示
- 従業員ID、従業員名、階層レベルを表示
- 階層レベル0が本人、1が直属上司

### 問題2-4: 部下の総数計算
各管理者について、直属・間接を含む全ての部下の人数を計算してください。

**要求事項:**
- 管理者ID、管理者名、直属部下数、全部下数を表示
- 管理者でない従業員は除外

### 問題2-5: 階層別予算集計
各部門の予算と、配下部門の予算合計を計算してください。

**要求事項:**
- 部門ID、部門名、自部門予算、配下部門予算合計、総予算を表示
- 配下部門がない場合は自部門予算のみ

### 問題2-6: カテゴリの階層パス
商品カテゴリの階層パスを生成してください。

**要求事項:**
- カテゴリID、カテゴリ名、階層パス（例：「家電 > コンピュータ > ノートPC」）を表示
- 区切り文字は「 > 」を使用

### 問題2-7: 連続する日付の生成
指定した期間（例：2022年1月1日〜2022年12月31日）の全ての日付を生成してください。

**要求事項:**
- 日付、曜日、月、四半期を表示
- 土日祝日フラグも含める（簡易版：土日のみ）

### 問題2-8: フィボナッチ数列
フィボナッチ数列の最初の20項を生成してください。

**要求事項:**
- 項番、フィボナッチ数を表示
- 1, 1, 2, 3, 5, 8, 13, ...の順序

### 問題2-9: 階層の最大深度計算
組織階層の最大深度を計算してください。

**要求事項:**
- 各ルート部門から最も深い階層までの深度を表示
- ルート部門名、最大深度を表示

### 問題2-10: 同階層の兄弟部門
各部門の同階層にある兄弟部門を表示してください。

**要求事項:**
- 部門ID、部門名、同階層の兄弟部門一覧を表示
- 自分自身は除外

### 問題2-11: 階層構造の検証
組織階層に循環参照がないかチェックしてください。

**要求事項:**
- 循環参照がある場合はその経路を表示
- 正常な場合は「循環参照なし」を表示

### 問題2-12: 複雑な階層集計
各部門について、配下の従業員の平均給与と総給与を階層的に集計してください。

**要求事項:**
- 部門ID、部門名、階層レベル、従業員数、平均給与、総給与を表示
- 配下部門の従業員も含めて集計

## セクション3: 共通テーブル式（CTE）の高度な活用（15問）

### 基本データ
以下のテーブル構造を前提とします：

```sql
-- 注文テーブル
CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    customer_id INT,
    order_date DATE,
    total_amount DECIMAL(10,2),
    status VARCHAR(20) -- 'PENDING', 'COMPLETED', 'CANCELLED'
);

-- 注文明細テーブル
CREATE TABLE order_items (
    order_item_id SERIAL PRIMARY KEY,
    order_id INT,
    product_id INT,
    quantity INT,
    unit_price DECIMAL(10,2)
);

-- 顧客テーブル
CREATE TABLE customers (
    customer_id SERIAL PRIMARY KEY,
    customer_name VARCHAR(100),
    email VARCHAR(255),
    registration_date DATE,
    customer_type VARCHAR(20)
);
```

### 問題3-1: 段階的な売上分析
月別売上、前月比、累積売上を段階的に計算してください。

**要求事項:**
- CTE1: 月別売上集計
- CTE2: 前月比計算
- CTE3: 累積売上計算
- 最終結果: 年月、月別売上、前月比（%）、累積売上

### 問題3-2: 顧客セグメンテーション
RFM分析による顧客セグメンテーションを実装してください。

- CTE1: 顧客別RFM指標計算

- CTE3: セグメント分類

- CTE1: 注文別商品リスト

### 問題3-4: 売上予測分析

### 問題3-5: 顧客ライフタイムバリュー

### 問題3-7: 季節性分析

### 問題3-14: 売上予算達成分析

## 学習のヒント

### 効果的な問題解決アプローチ

1. **要求分析**
   - 問題文を詳細に読み、要求事項を整理
   - 入力と出力を明確に定義
   - 制約条件の確認

2. **段階的アプローチ**
   - 複雑な問題を小さな部分に分解
   - 各部分を個別に解決
   - 最終的に統合

3. **実行計画の確認**
   - EXPLAINを使用して実行計画を確認
   - ボトルネックの特定
   - 最適化の実施

4. **テストデータの準備**
   - 適切なテストデータの作成
   - エッジケースの考慮
   - 結果の検証

### よくある間違いと対策

1. **ウィンドウ関数**
   - フレーム句の指定忘れ
   - パーティション分割の誤り
   - ORDER BYの省略

2. **再帰クエリ**
   - 無限ループの発生
   - 終了条件の設定ミス
   - パフォーマンスの劣化

3. **CTE**
   - 複雑すぎる構造
   - パフォーマンスの考慮不足
   - 可読性の低下

4. **トランザクション**
   - デッドロックの発生
   - 分離レベルの選択ミス
   - ロック時間の長期化

### パフォーマンス最適化のポイント

1. **インデックス活用**
   - 適切なインデックスの作成
   - 複合インデックスの順序
   - 部分インデックスの活用

2. **クエリ最適化**
   - JOINの順序最適化
   - サブクエリの書き換え
   - 不要な列の除外

3. **データ型の選択**
   - 適切なデータ型の使用
   - 文字列長の最適化
   - NULLの適切な使用

4. **統計情報**
   - 定期的な統計更新
   - カスタム統計の作成
   - 統計情報の確認
