# React 学習教材変換プロンプト

## 目的

原文の学習教材を、画面や開発環境を見なくても理解できる自立学習可能な日本語教材に変換する。

## 変換の基本方針

### 1. 原文内容の完全保持

- 原文の内容を省略せず、すべての情報を日本語版に含める
- 技術的な詳細や補足説明も漏れなく変換
- 学習の連続性を保つため、段階的な内容構成を維持

### 2. 語り口調での解説作成

- 箇条書きではなく、自然な語り口調で説明
- 学習者との対話を意識した親しみやすい文体
- 概念の理解を深める丁寧な説明展開

### 3. 最終プロジェクト完成への貢献

- 各 STEP が最終的なプロジェクト完成に必要な要素であることを確認
- 学習内容が実際のアプリケーション開発にどう活用されるかを明記
- 前後の STEP との関連性と積み重ねの重要性を説明

### 4. 自立学習可能性の確保

- 画面や図表を見ることを前提とした説明がある場合、それを明示して画像の作成を促すこと
- すべての概念を文章で完全に説明
- 実行結果や期待値を明確に記載

### 5. 日本語での技術学習最適化

- 丁寧語を基本とした分かりやすい説明
- 技術用語は英語併記で理解を促進
- 学習者の段階に応じた詳細度調整

## 必須変換ルール

### A. 画像・図表参照の処理

```markdown
❌ 変換前：
<img src="assets/image.png" alt="複雑なUI" />
この複雑な UI を見てみましょう

✅ 変換後：

### 複雑な UI の構造例

例えば、学習プラットフォームのような複雑な Web アプリケーションは以下の構造になります：

**大きなコンポーネント**：

- **ビデオプレーヤー**：動画の再生・制御機能
- **ナビゲーションメニュー**：サイト内移動機能
- **コンテンツエリア**：学習内容の表示領域

**小さなコンポーネント**：

- **再生ボタン**：動画の開始/停止
- **進捗バー**：再生位置の表示
- **音量調整**：音声レベルの制御
```

### B. 指示語の具体化と語り口調での説明

```markdown
❌ 変換前：
ここで JSX が登場します
右側のこのコードのようになります
そこで、これを見ると

✅ 変換後：
さて、ここで React の重要な概念である JSX が登場します。JSX は、JavaScript の中で HTML のような記法を使ってコンポーネントの外観を定義できる構文です。これにより、私たちは直感的に UI を記述することができるようになります。

実際に、Babel というツールがこの JSX を通常の JavaScript コードに変換してくれます。変換後のコードを見てみると、React.createElement()という関数呼び出しに変わっていることが分かります。

この実行結果を詳しく見てみましょう。出力された内容から、React がどのようにコンポーネントを処理しているかが理解できます。
```

### C. 開発ツール操作の詳細化

```markdown
❌ 変換前：
コンソールをチェックしてみましょう
Problems タブにも表示されます

✅ 変換後：

### ブラウザ開発者ツールでの確認方法

1. **開き方**：F12 キーまたは右クリック → 「検証」
2. **Console タブの使用**：
   - 場所：開発者ツール上部のタブ
   - 機能：JavaScript の実行結果やエラーメッセージを表示
   - 確認内容：`console.log()`の出力結果

### VS Code での問題確認

1. **Problems タブ**：
   - 場所：VS Code 下部のパネル（ターミナルの隣）
   - 機能：ESLint の警告や TypeScript のエラーを表示
   - 使い方：黄色い波線が表示されたコードの詳細を確認
```

### D. 実行結果の明確化

````markdown
❌ 変換前：
保存すると、そこにあります、変わりました
コンソールで数字の 9 があります

✅ 変換後：

### 期待される実行結果

ファイルを保存すると、ブラウザで以下の変化が確認できます：

- **背景色**：白から薄いグレーに変更
- **フォント**：デフォルトから Roboto に変更
- **ボーダー**：ページ下部に黄色い線が表示

### コンソール出力例

```javascript
const hour = new Date().getHours();
console.log(hour);
```
````

**出力結果**：

- 午前 9 時の場合：`9`
- 午後 3 時の場合：`15`
- 現在時刻に応じた 0-23 の数値が表示されます

````

## 品質チェックポイント

### 1. 原文内容の完全性チェック
- [ ] 原文のすべての技術的内容が含まれているか
- [ ] 重要な概念や手順が省略されていないか
- [ ] 原文の学習目標が適切に反映されているか

### 2. 語り口調と説明品質チェック
- [ ] 箇条書きではなく自然な語り口調になっているか
- [ ] 学習者との対話を意識した親しみやすい文体か
- [ ] 概念の理解を深める丁寧な説明展開になっているか

### 3. 最終プロジェクトとの関連性チェック
- [ ] 学習内容が最終プロジェクト(finalディレクトリ)完成に必要な要素であることが明確か
- [ ] 実際のアプリケーション開発での活用方法が説明されているか
- [ ] 前後のSTEPとの関連性と積み重ねの重要性が示されているか

### 4. 自立性チェック
- [ ] 画面を見なくても理解できる説明になっているか
- [ ] すべての指示語が具体的な説明に置き換えられているか
- [ ] 実行結果の期待値が明記されているか

### 5. 学習効果チェック
- [ ] 概念の説明が段階的で理解しやすいか
- [ ] コード例に十分な文脈説明があるか
- [ ] なぜそのコードが必要なのかが説明されているか

### 6. 技術的一貫性チェック
- [ ] コードブロックの書式が統一されているか
- [ ] 専門用語の日本語表記が一貫しているか
- [ ] ファイル構造や命名規則が明確に説明されているか

## 変換作業の手順

### Step 1: 原文内容の完全把握
1. 原文のすべての技術的内容を確認
2. 学習目標と最終プロジェクトとの関連性を理解
3. 前後のSTEPとの連続性を把握
4. 省略してはいけない重要な概念を特定

### Step 2: 問題箇所の特定
1. 画像参照（`<img>`タグ、図表への言及）を検索
2. 指示語（「ここで」「そこで」「これを見ると」）を検索
3. 開発ツール操作の曖昧な説明を特定
4. 実行結果の不明確な記述を特定
5. 箇条書きで説明されている部分を特定

### Step 3: 語り口調での改善テンプレート適用
1. 画像参照 → 詳細なテキスト説明に変換（語り口調で）
2. 指示語 → 具体的で親しみやすい説明に変換
3. 開発ツール操作 → 対話的な手順詳細化
4. 実行結果 → 期待値を自然な文章で明記
5. 箇条書き → 流れのある語り口調の説明に変換

### Step 4: 最終プロジェクトとの関連性明記
1. 学習内容が最終プロジェクトでどう活用されるかを説明
2. 実際のアプリケーション開発での重要性を強調
3. 前後のSTEPとの積み重ねの意味を明確化

### Step 5: 品質検証
1. 原文内容の完全性確認
2. 語り口調と説明品質の確認
3. 最終プロジェクトとの関連性確認
4. 自立学習可能性の確認
5. 日本語として自然な文章の確認
6. 技術的正確性の確認

## 出力形式

変換後のファイルは以下の構造で出力：

```markdown
# Session[N]_学習内容.md

## 学習目標
（明確な学習目標と最終プロジェクトでの活用方法を記載）

## 学習内容
（原文の内容を省略せず、語り口調で自立学習可能な詳細説明）


## まとめ
（学習内容の要点整理と最終プロジェクトへの貢献を語り口調で説明）

## 次のステップ
（次の学習内容への橋渡しと積み重ねの重要性を説明）
````

このプロンプトに従って変換作業を実行し、自立学習可能な高品質な日本語学習教材を作成してください。
