# DRY 原則 (Don't Repeat Yourself) in Angular

## 概念: 重複の悪
『達人プログラマー』における DRY 原則は、単に「同じコードを書くな」という意味ではありません。
真の定義は **「システム内の知識は、単一の、明確な、信頼できる表現を持たなければならない」** です。

同じコードが2箇所にあっても、それぞれが異なる理由（知識）を表しているなら、それは重複ではありません。
逆に、コードが全く違っても、同じビジネスルール（例: 消費税計算）をハードコードしていたら、それは重複（知識の二重化）です。

## Angular における DRY の実践

Angular には知識を単一化するための強力な仕組みが備わっています。

### 1. Directive (振る舞いの DRY)
「マウスオーバーで色を変える」「クリック外を検知する」といった**DOM操作の知識**を、コンポーネントごとに書くのではなく、Directive に抽出します。

### 2. Pure Pipe (データ変換の DRY)
「日付のフォーマット」「通貨の表示」といった**表示ロジックの知識**をPipeに抽出します。View 内で関数を直接呼ぶよりも、宣言的で再利用性が高まります。

### 3. Service / Utility (ロジックの DRY)
HTTPリクエストのエラーハンドリングや、共通の計算ロジックを一箇所にまとめます。

## 学習用ファイル

1. `highlight.directive.ts`
   - UIの振る舞い（ホバー効果）を再利用可能にした Directive。
2. `format-date.pipe.ts`
   - 日付変換ロジックを再利用可能にした Pipe。
3. `api-client.service.ts`
   - API通信における共通設定（BaseURL や ヘッダー処理）をまとめた Service。
