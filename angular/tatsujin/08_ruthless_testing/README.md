# 冷酷なテスト (Test to Ruthlessness) in Angular

## 概念: バグを殲滅する意思
多くの開発者は「テストを通す」ためにテストを書きます。
しかし達人は「コードを破壊（バグを発見）する」ためにテストを書きます。このマインドセットの違いが品質の決定的な差になります。

### 何をテストするか？
1. **境界値 (Boundary Analysis)**: 配列が空の時、要素が1つの時、巨大な数の時。
2. **異常系 (Negative Testing)**: サーバーが500を返した時、ネットワークが切れた時。
3. **契約違反**: 事前条件を満たさない入力を渡した時に、正しくエラーを吐くか。

## 学習用ファイル

1. `calc.service.spec.ts`
   - 単純な計算ロジックですが、ゼロ除算や負の数など、意地悪なケースを網羅します。
2. `isolated-component.spec.ts`
   - Angular TestBed を使わず、コンポーネントを純粋な TypeScript クラスとしてテストする高速な手法。
