### ローカル状態とグローバル状態の違い

React では、各状態はローカル状態またはグローバル状態のいずれかです。

#### ローカル状態（Local State）

ローカル状態は、1 つのコンポーネントまたは少数の異なるコンポーネント（子コンポーネントや兄弟コンポーネントなど）でのみ必要な状態です。

私たちは、特定のコンポーネント内で useState 関数を使用してローカル状態を作成します。

そして、その状態は、その正確なコンポーネントと、props を使用して状態を渡す場合はその子コンポーネントからのみアクセス可能です。

Udemy アプリに戻ると、ローカル状態の例は検索バーの入力テキストかもしれません。

おそらくそのコンポーネントだけがこのデータについて知る必要があります。

したがって、これはローカル状態です。つまり、その検索バーコンポーネントにローカルな状態です。

#### グローバル状態（Global State）

グローバル状態について言えば、これはアプリ内の多くの異なるコンポーネントがアクセスする必要がある状態です。

したがって、状態をグローバルとして定義すると、その状態はアプリ全体のすべてのコンポーネントからアクセス可能になります。

これはすべてのコンポーネント間で共有されるため、これを共有状態とも呼ぶことができます。

実際には、React の Context API または Redux のような外部のグローバル状態管理ライブラリを使用してグローバル状態を定義できます。

この Udemy アプリでは、グローバル状態の 1 つはショッピングカートです。

そのデータはここのあちこちで使用されています。

これらすべてのコンポーネントがショッピングカートの状態にアクセスする必要があるため、これがグローバル状態であることは理にかなっています。

## 「状態のリフトアップ」の復習

さて、前のビデオで実装した状態のリフトアップについて、もう少し詳しく説明し、復習してみましょう。

状態のリフトアップは、React における非常に重要な概念の 1 つです。

### 状態のリフトアップとは

状態のリフトアップとは、複数のコンポーネントが同じ状態にアクセスする必要がある場合に、その状態を共通の親コンポーネントに移動することです。

これにより、データの一元管理が可能になり、複数のコンポーネント間でデータを共有できるようになります。

### 実装したコードの詳細解説

前のビデオで実装したコードを詳しく見てみましょう：

#### 1. App コンポーネント（親コンポーネント）

```jsx
function App() {
  const [items, setItems] = useState([]); // 状態をここに配置

  function handleAddItems(item) {
    setItems((items) => [...items, item]); // 状態更新ロジック
  }

  return (
    <div className="app">
      <Logo />
      <Form onAddItems={handleAddItems} /> {/* 関数をpropsで渡す */}
      <PackingList items={items} /> {/* 状態をpropsで渡す */}
      <Stats items={items} />
    </div>
  );
}
```

#### 2. Form コンポーネント（子コンポーネント）

```jsx
function Form({ onAddItems }) {
  // 関数をpropsで受け取る
  const [description, setDescription] = useState("");
  const [quantity, setQuantity] = useState(1);

  function handleSubmit(e) {
    e.preventDefault();

    if (!description) return;

    const newItem = {
      description,
      quantity,
      packed: false,
      id: Date.now(),
    };

    onAddItems(newItem); // 親から受け取った関数を呼び出し

    setDescription("");
    setQuantity(1);
  }

  // JSX部分...
}
```

#### 3. PackingList コンポーネント（子コンポーネント）

```jsx
function PackingList({ items }) {
  // 状態をpropsで受け取る
  return (
    <div className="list">
      <ul>
        {items.map((item) => (
          <Item item={item} key={item.id} />
        ))}
      </ul>
    </div>
  );
}
```

### データフローの詳細

状態のリフトアップ後のデータフローを詳しく見てみましょう：

#### アイテム追加の完全なフロー

1. **ユーザーの入力**：

   - ユーザーが Form コンポーネントで商品名と数量を入力
   - 送信ボタンをクリック

2. **イベントの発生**：

   - `handleSubmit`関数が実行される
   - 新しいアイテムオブジェクトが作成される

3. **親コンポーネントへの通知**：

   - `onAddItems(newItem)`が呼び出される
   - これは実際には App 内の`handleAddItems`関数

4. **状態の更新**：

   - App 内の`handleAddItems`が実行される
   - `setItems`によって items 配列が更新される

5. **再レンダリングの連鎖**：
   - App コンポーネントが再レンダリングされる
   - 新しい items が PackingList に props として渡される
   - PackingList が再レンダリングされ、新しいアイテムが表示される

### 状態のリフトアップの利点

1. **データの一元管理**：

   - すべてのアイテムデータが 1 箇所（App）で管理される
   - データの整合性が保たれる

2. **コンポーネント間の連携**：

   - Form で追加されたアイテムが即座に PackingList に反映される
   - 将来的に Stats コンポーネントでも同じデータを使用可能

3. **単方向データフロー**：
   - データは親から子へ（props）
   - イベントは子から親へ（関数呼び出し）
   - React の設計原則に従った実装

### 関数を props として渡すパターンの詳細

このパターンは非常に重要で、React アプリケーションでよく使用されます：

```jsx
// 親コンポーネント
function Parent() {
  const [state, setState] = useState(initialValue);

  function handleStateChange(newValue) {
    setState(newValue);
  }

  return <Child onStateChange={handleStateChange} />;
}

// 子コンポーネント
function Child({ onStateChange }) {
  function handleClick() {
    onStateChange(someValue); // 親の状態を更新
  }

  return <button onClick={handleClick}>Update Parent State</button>;
}
```

### 命名規則の重要性

適切な命名規則により、コードの意図が明確になります：

- **親コンポーネントの関数**：`handle〜`（例：`handleAddItems`）

  - 実際の処理を行う関数であることを示す

- **props の名前**：`on〜`（例：`onAddItems`）
  - イベントハンドラーであることを示す
  - HTML のイベント属性（onClick、onSubmit など）と一貫性がある

### 不変性の重要性

状態更新時の不変性について詳しく説明します：

```jsx
function handleAddItems(item) {
  // ❌ 間違った方法：既存の配列を変更（ミューテーション）
  // items.push(item);
  // setItems(items);

  // ✅ 正しい方法：新しい配列を作成
  setItems((items) => [...items, item]);
}
```

**なぜ不変性が重要なのか：**

1. **React の変更検出**：

   - React は参照の比較で変更を検出
   - 同じ参照だと変更されていないと判断される

2. **予測可能な動作**：

   - 状態の変更が確実に再レンダリングを引き起こす
   - デバッグが容易になる

3. **パフォーマンス最適化**：
   - React.memo や useMemo などの最適化が正しく動作する

### よくある間違いとデバッグ方法

状態のリフトアップ実装時によくある間違い：

1. **props の受け渡し忘れ**：

   ```jsx
   // ❌ 間違い
   <Form /> // onAddItemsを渡していない

   // ✅ 正しい
   <Form onAddItems={handleAddItems} />
   ```

2. **props の受け取り忘れ**：

   ```jsx
   // ❌ 間違い
   function Form() { // propsを受け取っていない

   // ✅ 正しい
   function Form({ onAddItems }) {
   ```

3. **関数名の間違い**：

   ```jsx
   // ❌ 間違い
   onAddItems(newItem); // 関数が定義されていない

   // ✅ 正しい
   onAddItems(newItem); // propsで受け取った関数を使用
   ```

状態のリフトアップは、React アプリケーション開発における基本的で重要な概念です。

**重要なポイント：**

1. **共有が必要な状態は共通の親に配置する**
2. **関数を props として渡すことで子から親の状態を更新する**
3. **適切な命名規則（handle〜 / on〜）を使用する**
4. **配列やオブジェクトの更新時は不変性を保つ**
5. **React DevTools を活用してデータフローを確認する**
