## 🚀 ルートコンポーネントのレンダリングとStrictMode

### プロジェクトの初期設定

ピザメニュープロジェクトの構築を完全にゼロから始めましょう。

まず、不要なファイルをすべて削除し、プロジェクトを一から作成します。ブラウザを右側に、コードエディタを左側に配置して、常に出力を確認できるようにしましょう。

### React 18での基本セットアップ

最初のファイル `index.js` を作成します。このファイル名は重要です。なぜなら、webpack（このプロジェクトのモジュールバンドラー）は、エントリーポイントが `index.js` という名前であることを期待しているからです。

```javascript
// 基本的なReactライブラリのインポート
import React from 'react';
import ReactDOM from 'react-dom/client';
```

これらは単純なJavaScriptのモジュールインポートです。ES6以降のJavaScriptの機能を使用しています。

### Appコンポーネントの作成

```javascript
function App() {
  return <h1>Hello React!</h1>;
}
```

**重要なルール**：
- コンポーネント名は**大文字で始める**必要があります
- 関数は何らかのマークアップ（通常はJSX）を返す必要があります

### React 18でのレンダリング方法

```javascript
// React 18の新しいレンダリング方法
const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(<App />);
```

この方法は、public/index.htmlファイル内の `id="root"` を持つdiv要素を選択し、そこにReactアプリケーションをレンダリングします。

### React 17以前との違い

参考として、React 17以前では以下のような書き方でした：

```javascript
// React 17以前の方法（参考用）
// ReactDOM.render(<App />, document.getElementById('root'));
```

### StrictModeの活用

```javascript
const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
```

**StrictModeの効果**：
- 開発中にすべてのコンポーネントを2回レンダリングしてバグを発見
- 古いReact APIの使用をチェック
- 開発時のみ動作（本番環境では影響なし）

StrictModeは画期的な機能ではありませんが、Reactアプリケーション開発時には常に有効にすることをお勧めします。

## 🔧 コーディング開始前に：デバッグ技術

### 実際の開発で直面する問題への準備

これから、あなたは自分のコンピューターでコーディングを始めることになります。そして、エラーが発生し、いくつかのことが単純にうまくいかないことはほぼ確実です。

そこで、この講義の最初から、これらのエラーや問題に対処するためのいくつかのテクニックをお見せしたいと思います。これは本当に重要な講義なので、スキップしないでください。

### アプリケーションが更新されない場合の対処法

コードで何らかの変更を行い、それを保存して、出力を見たいとしましょう。しかし、何らかの理由で、ページがここで更新されなかったと想像してください。そのような場合、どうしますか？

そのようなことが起こったとき、パニックにならず、代わりに、これからお話しするいくつかの解決策を試してみてください。

最初の解決策は、アプリケーションが実際に動作していることを確認することです。信じられないかもしれませんが、これは実際に私にも起こったことがあります。アプリが動作していると思っていて、コードに何らかの更新を行い、何かを変更していたのですが、なぜアプリがリロードされないのか疑問に思っていました。そして、ある時点で、実際にはアプリを起動していなかったことに気づいたのです。

これは実際に起こりうることです。したがって、アプリが動作していない場合、つまり、先ほどお見せしたように「npm start」を使用していない場合、もちろんアプリはブラウザでリロードできません。

しかし、実際に動作していることが確実だが、それでも更新されない場合、一つの解決策は、アプリを停止して再起動することです。

ここに、現在アプリが動作しているターミナルのタブがあります。それを停止するために、Control + Cを使用します。Macでは、それはControl + Cで、Windowsでも同じくControl + Cです。Windowsでは、実際に停止したいかどうか尋ねられるかもしれません。その場合は、'Y'と入力してEnterを押すことができます。

これで停止し、再起動できます。それは再び「npm start」です。これで新しいタブが開かれるはずです。

実際、あなたが思っているよりも、このようなことをしなければならないことは一般的です。だからこそ、私は本当にこの講義を早い段階で含めたかったのです。

### ブラウザのハードリロードの重要性

また、非常に一般的なのは、時々、ここでブラウザでハードリロードを行うだけで済むことです。このリロードボタンをクリックするだけです。なぜなら、この自動リロード、つまりホットモジュールリプレースメントが、何らかの理由で常に壊れるからです。

そのため、解決策の一つは、ブラウザをハードリロードすることです。

### 開発環境の適切な設定

私があなたに与えることができるもう一つの良いヒントは、常にここでターミナルを開いておくことです。そして、ブラウザの開発ツールについても同様です。

検査して、ここでコンソールを開いておくことです。React開発ツールというものもありますが、それについては少し後で話します。

これらを開いておくことは良いことです。なぜなら、予期しないエラーがある場合、それらはこのコンソールとここの下にも表示されるからです。また、これを開いておけば、アプリが動作していることを常に確認できます。

### エラーメッセージの理解と活用

先ほどエラーメッセージについて話しましたが、何か間違ったことをすると、時々これらが表示されます。Create React Appには、ウィンドウの上に、つまりアプリの上にエラーを自動的に表示する内部的な仕組みがあります。

それをお見せしましょう。ここで何かエラーを作成するものを書きます。

実際、ここにエラーがあります。時々、重要なエラーがここに表示されますが、アプリ全体にこのオーバーレイがあり、このエラーメッセージを提供してくれます。

そして、このエラーメッセージを見て、実際に何が間違っていたかを理解しようとすることは良いアイデアです。通常、この最初の部分はあまり重要ではありませんが、ここでは「隣接するJSX要素は囲むタグでラップされなければならない。JSXフラグメントが欲しかったのですか？」と言っています。

そして、これを本当に理解できない場合は、これをコピーして、新しいタブを開いてGoogleで検索することができます。

これが今、Reactの巨大なコミュニティの力です。なぜなら、あなたの前に何百人、何千人もの人々が同じ問題を抱え、Googleで検索したり、Stack Overflowで質問したりしているからです。そして、そこで答えを見つけることができるでしょう。

### ESLintの活用

もう一つの重要なヒントは、常にESLintと連携することです。ESLintはデフォルトで有効になっています。例えば、これを行うと、const x = 'jonas'と書いて保存すると、すぐにここで警告が表示されます。

これは無数の例や状況の一つに過ぎません。ESLintは、あなたがすべきでないことをしようとしていることを警告してくれます。なぜなら、使用していない変数がある場合、それはおそらくどこか他の場所で、実際に意図していなかった間違った変数を宣言したことを意味するからです。

ちなみに、これらの問題は、ここの下のProblemsタブにも表示されます。これもここで非常に有用です。したがって、コードの下にこのような黄色い線がある場合は、そこで何が起こっているかをチェックすべきです。

さて、コードですべてが正しく見え、私が言ったすべてのことを行ったが、それでもコードが動作しない場合、おそらくコードにバグがあることを意味します。なぜなら、ビデオで見せているものとは異なるからです。

## 🧱 コンポーネント：構成要素としての概念

### コンポーネントとは何か

コンポーネントはReactの最も基本的な概念です。そして、これを理解することは非常に重要です。なぜなら、Reactアプリケーションは文字通り完全にコンポーネントで構成されているからです。

実際にReactアプリケーションを見てみると、コンポーネントでないものや、少なくとも何らかのコンポーネントの内部にないものは存在しません。したがって、私はコンポーネントをReactにおけるユーザーインターフェースの構成要素と呼ぶのが好きです。

実際、Reactが行うことは基本的に、コンポーネントを取得してそれらをWebページ、つまりユーザーインターフェース（略してUI）に描画することです。これは単純に聞こえるかもしれませんが、実際にはReactの主要な仕事なのです。

より技術的な用語で言えば、Reactは各コンポーネントに対してビューをレンダリングし、これらすべてのビューが一緒になってユーザーインターフェースを構成します。したがって、コンポーネントをユーザーインターフェースの一部として考えることもできます。

### コンポーネントの重要な特性

コンポーネントの重要な特性の一つは、各コンポーネントが独自のデータ、JavaScriptロジック、そして外観を持つということです。基本的に、各コンポーネントは自分がどのように動作し、どのように見えるかを記述します。これにより、コンポーネントはユーザーインターフェースを構築するための素晴らしい方法となっています。

そして、ユーザーインターフェースの構築について話すとき、私たちが今学んだことに基づいて、Reactでは複雑なUIを構築する際に、複数のコンポーネントを構築し、それらをレゴのピースのように組み合わせることが理にかなっています。

### 複雑なUIの構築：実例による理解

例えば、この複雑なUIを見てみましょう。ここでは、ビデオプレーヤー、メニュー、この質問リスト、そして表示される質問を絞り込むことができるこの部分など、大きなコンポーネントを特定することができます。これらが大きなコンポーネントですが、このUIには他にも多くの小さなコンポーネントを特定することができます。例えば、これらのフィルターなどです。

<img src="assets/image-20250831140106062.png" alt="image-20250831140106062" style="zoom:50%;" />

そして、このフィルターが絞り込み質問コンポーネントの内部にあることがわかります。実際、私たちが常に行うことの一つは、コンポーネントを他のコンポーネントの内部に配置すること、つまり、コンポーネントを互いにネストすることです。

### コンポーネントの再利用性：重複の解決

コンポーネントをネストすることは、Reactでコンポーネントを使用する際の重要な側面の一つです。そして、コンポーネントの再利用性も同様に重要です。

質問リストに3つの類似した質問があることに注目してください。そこで、1つの質問コンポーネントを作成し、それをここで3回再利用することができます。もちろん、それぞれのデータは異なりますが、propsと呼ばれるものを使用して、異なる質問コンポーネントに異なるデータを簡単に渡すことができます。propsについては後で詳しく説明します。

したがって、UIで何らかの重複が必要な場合は常に、新しいコンポーネントを作成し、必要な回数だけ使用します。

### コンポーネント分析の重要なスキル

ご覧のように、このコースを通じて学ぶ重要なスキルの一つは、このようなデザインをコンポーネントに分解する方法です。

そして、これを支援し、私たちが作成するコンポーネントを分析するのに役立つものの一つが、このようなコンポーネントツリーです。これは、ユーザーインターフェースを構成するコンポーネント間に存在する階層を示しており、これらすべてのコンポーネントがどのように互いにネストされているか、そして実際にどのように関連しているかを理解することを非常に簡単にします。

### 親子関係の理解

また、コンポーネント間の関係も明確に見ることができます。例えば、絞り込み質問がフィルターの親コンポーネントであること、または逆に言えば、フィルターが絞り込み質問の子コンポーネントであることなどです。

私たちは、親コンポーネントと子コンポーネントという用語をReactで常に使用します。したがって、これらが何を意味するかを理解することが重要です。このようなコンポーネントツリーは、コンポーネント間のこのような関係を理解するのに最適です。

これで、今のところコンポーネントについて知っておく必要があることはすべてです。再利用性などの重要な概念については後で詳しく説明しますが、今のところは、これらの概念の一部を実践に移しましょう。

### アプリケーション開発の継続

新しいコンポーネントを作成し、再利用性について最初に見てみることで、アプリケーションの構築を続けましょう。

しかし、まず最初に、GitHubからダウンロードしたファイルから、このプロジェクトのスターターファイルを取得しましょう。

### スターターファイルの準備

スターターフォルダから、これら3つのファイルを取得し、コピーして、プロジェクトフォルダに移動します。今のところ、これらをpublicフォルダにコピーします。

**必要なファイル**：

スターターファイルを含めた後、これら2つのファイルがここにあることを確認してください。

### 新しいコンポーネントの作成

それでは、ここに戻って、私が話していた新しいコンポーネントを作成しましょう。

Reactでは、関数を使用して新しいコンポーネントを作成します。

```javascript
function Pizza() {
  return <h2>Pizza</h2>;
}
```

ピザに関するデータを含むので、これをPizzaと呼んでいます。今のところ、この関数にはパラメータはなく、関数本体があります。

### コンポーネント作成の重要なルール

Reactで関数としてコンポーネントを書く際には、2つの重要なルールがあります。

**第一に、関数名は大文字で始める必要があります**。このようにです。

**第二に、関数は何らかのマークアップを返す必要があります**。通常はJSXの形で、しかし何も返さない、つまりnullを返すことさえできます。

しかし、ここでは、例えばH2要素を返して、「pizza」と書きましょう。

保存しても、もちろんユーザーインターフェースには何も表示されません。それは、この新しいコンポーネントをどこにも含めていないからです。ESLintもここで警告しています。

この黄色い線は「pizzaが定義されているが、使用されていない」と言っています。

### コンポーネントの使用

つまり、現在画面にレンダリングされているコンポーネントであるappコンポーネントに、このpizzaコンポーネントを含めていないのです。

このようにコンポーネントを使用できます：

```javascript
function App() {
  return (
    <div>
      <h1>Hello React!</h1>
      <Pizza />
    </div>
  );
}
```

Pizzaと書いて、すぐに要素を閉じます。

しかし、これはエラーを発生させます。以前にも見たことがあるエラーです。このエラーの理由は、各コンポーネントは正確に1つの要素のみを返すことができ、ここにあるような2つの要素は返せないからです。

そこで、これをdivでラップしましょう。VS Codeが自動的にこれらの要素を閉じるのが少し煩わしくなることがありますが、とにかく、今度はUIにピザが表示されます。

### コンポーネントのネスト

これは、このpizzaコンポーネントをこのappコンポーネント内にネストしたからです。

ネストとは、基本的にこのコンポーネントをapp内で使用した、または呼び出したということです。

**非常に重要な注意点**：ネストとは、この他の関数内に関数を書くことを意味するのではありません。

```javascript
// ❌ 絶対にやってはいけないこと
function App() {
  function Pizza() { // これは非常に悪いアイデア
    return <h2>Pizza</h2>;
  }
  return <div><Pizza /></div>;
}
```

これは実際にはまだ動作しますが、後で学ぶ理由により、非常に悪いアイデアです。

**したがって、関数宣言をネストしてはいけません。常にすべてのコンポーネントをトップレベルで宣言してください。**

```javascript
// ✅ 正しい方法
function Pizza() {
  return <h2>Pizza</h2>;
}

function App() {
  return (
    <div>
      <Pizza />
    </div>
  );
}
```

つまり、コンポーネントをネストすると言うとき、私たちが意味するのは、このように1つのコンポーネントを別のコンポーネントに呼び出す、つまり含めることです。

### より興味深いコンポーネントの作成

さて、このpizzaコンポーネントをもう少し興味深いものにしましょう。そのために、ここのスターターデータを使用します。

data.jsを開いて、すべてを選択し、コピーして、ここに貼り付けます。

実際に、このdata.jsを削除して、これを閉じることができます。

```javascript
function Pizza() {
```

### 画像の使用

さて、テキストがあるので、publicフォルダにあるこの画像も実際に使用しましょう。

最初に述べたように、アプリのすべてのアセットはこのpublicフォルダに入ります。なぜなら、Webpack（モジュールバンドラー）が基本的に自動的にそこからそれらを取得するからです。

### コンポーネントの再利用

このコンポーネントがあり、今度はこのコンポーネントを再利用するアイデアについて話しましょう。

今のところ、このコンポーネントを再利用するために行うことは、基本的に何度か使用することです。

```javascript
function App() {
  return (
    <div>
      <h1>Hello React!</h1>
      <Pizza />
      <Pizza />
      <Pizza />
    </div>
  );
}
```

3回やってみましょう。そうすれば、このUIの部分、つまりpizzaコンポーネントが3回含まれることがわかります。

3回、このおいしいスピナッチピザ。素晴らしい。もちろん、ここのすべてのデータは現在同じです。なぜなら、まだそのデータをカスタマイズしていないからです。しかし、もちろん、propsについて話すときに、後でそれを行います。

### 再利用性の重要な概念

今のところ、UIの各部分、つまり各コンポーネントを複数回呼び出して再利用できるという、この本当に重要な概念を理解してほしいのです。これがReactアプリケーションを書く基本的な概念です。

### 開発環境の設定（オプション）

最後に、コードとは関係ありませんが、サイドバーやここの下にこれらの色付きの線がすべて表示されることに気づいたかもしれません。

この理由は、Create-React-Appで新しいプロジェクトを作成すると、実際に自動的にこのプロジェクトをGitHubリポジトリとして設定するからです。そのため、ここでもこれらの異なる色が表示され、また、異なるファイルに加えた変更もすべて表示されます。

これらの小さなプロジェクトを構築する際にGitHubを実際に使用するつもりはないので、実際にはガター、つまりこの場所からこれらの色付きの線を削除したいと思います。

そのために、設定に移動して、「diff decorations」を検索できます。ここでデフォルトは「all」なので、「none」に設定しましょう。

そうすれば、エディタがここでもう少しクリーンに見え、サイドバーを閉じることができます。これで、この講義を終了し、次に進む準備ができました。

## 🎯 重要なポイント

### React開発の基本原則

- **コンポーネント思考**：UIを小さな再利用可能な部品として考える
- **宣言的アプローチ**：「何を」表示するかに集中する
- **単一責任の原則**：各コンポーネントは1つの明確な役割を持つ

### 開発効率を上げるコツ

- **常にターミナルと開発者ツールを開いておく**
- **ESLintの警告に注意を払う**
- **エラーメッセージを恐れずに読む**
- **小さく始めて段階的に複雑にする**

### よくある間違いと対策

| 間違い | 正しい方法 | 理由 |
|--------|------------|------|
| 小文字でコンポーネント名を開始 | 大文字で開始 | Reactの規約 |
| 複数要素を直接返す | 1つの親要素でラップ | JSXの制限 |
| 関数内で関数を定義 | トップレベルで定義 | パフォーマンスの問題 |

このセッションで学んだ基礎知識は、React開発の土台となります。次のセッションでより高度な概念を学ぶ準備が整いました！
