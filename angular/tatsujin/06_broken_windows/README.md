# 割れ窓理論 (The Broken Window Theory) in Angular

## 概念: 崩壊は些細なことから始まる
「割れ窓理論」は、建物の窓がひとつ壊れているのを放置すると、誰も気にしなくなり、やがて全ての窓が壊され、建物全体が荒廃するという社会心理学の理論です。
ソフトウェア開発において、その「最初の割れ窓」とは何でしょうか？

- たった一つの `any` 型の使用
- コンソールに出続ける Warning メッセージ
- テストカバレッジのわずかな低下
- 定義されていない「とりあえず動く」ハック

これらを許容した瞬間、チーム全体に「品質は重要ではない」という暗黙のメッセージが伝わります。

## Angular における「窓を直す」活動

1. **No Any**: `any` はウイルスです。一つ許可すると、引数や戻り値を通じて伝染します。`Strict Mode` を有効にし、ジェネリック型を活用しましょう。
2. **Lint Everything**: ESLint / Prettier を強制し、機械的にコードの清潔さを保ちます。
3. **Zero Warnings**: ビルドログやコンソールログの Warning は「情報」ではなく「エラー予備軍」として即座に殲滅します。
