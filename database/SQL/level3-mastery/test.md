以下のSQLクエリの実行結果として正しいものはどれですか？

```sql

    SELECT 'A' as product, '2024-01-01'::DATE as sale_date, 100 as amount
    UNION ALL SELECT 'A', '2024-01-02'::DATE, 150
    UNION ALL SELECT 'A', '2024-01-03'::DATE, 120
    UNION ALL SELECT 'B', '2024-01-01'::DATE, 200
    UNION ALL SELECT 'B', '2024-01-02'::DATE, 180
)
SELECT 
    product,
    sale_date,
    amount,
    LAG(amount, 1, 0) OVER (PARTITION BY product ORDER BY sale_date) as prev_amount,
    LEAD(amount, 1, 0) OVER (PARTITION BY product ORDER BY sale_date) as next_amount
FROM sales_data
ORDER BY product, sale_date;
```

B) 商品Aの2024-01-01のprev_amountは0、next_amountは150
C) 商品Bの2024-01-02のprev_amountは200、next_amountはNULL
D) 商品Bの2024-01-02のprev_amountは200、next_amountは0

## 解答と解説

### 問題1: B
**解説:** LAG関数の第3パラメータ（デフォルト値）により、前の行がない場合は0が返されます。商品Aの最初の行（2024-01-01）のprev_amountは0、next_amountは次の行の150になります。

### 問題2: A
**解説:** NTILE(4)で13人を4グループに分ける場合、13÷4=3余り1となり、余りは最初のグループから順に配分されます。結果：4人、3人、3人、3人となります。

### 問題3: B
**解説:** アンカー部分で1を生成し、再帰部分でn+1を生成します。WHERE n < 5により、nが5未満の間継続するため、1から5までが生成されます。

### 問題4: C
**解説:** LAST_VALUE関数で最後の値を正しく取得するには、ウィンドウの範囲を明示的に指定する必要があります。ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWINGが必要です。

### 問題5: C
**解説:** CTEをサブクエリに書き換えることは必ずしも最適化にならず、むしろ可読性を損なう場合があります。CTEの利点を活かした設計が重要です。

### 問題6: C
**解説:** LIMIT句は結果件数を制限するだけで、無限ループ自体を防ぐことはできません。深度制限、循環参照チェック、親子関係チェックが有効な方法です。

### 問題7: C
**解説:** PARTITION BY customer_id ORDER BY order_dateに対応するため、(customer_id, order_date)の複合インデックスが最も効果的です。

### 問題8: B
**解説:** PostgreSQLのPL/pgSQLでは、BEGIN...EXCEPTION WHEN...ENDの構文を使用して例外処理を行います。

### 問題9: C
**解説:** BEFORE UPDATE FOR EACH ROWトリガーは、UPDATE文の実行前に、更新される各行に対して実行されます。

### 問題10: C
**解説:** READ COMMITTEDでは、同一トランザクション内でも他のトランザクションのコミット後に異なる結果を返す可能性があります（ノンリピータブルリード）。

### 問題11: C
**解説:** デッドロック回避の最も重要な原則は、リソースのロック順序を統一することです。これにより循環待機を防げます。

### 問題12: B
**解説:** 楽観的ロックは、バージョン番号やタイムスタンプを使用して競合を検出する方式です。

### 問題13: A
**解説:** WHERE条件の選択性とORDER BYを考慮すると、(customer_id, order_date, status)の順序が最適です。

### 問題14: B
**解説:** Seq Scan（Sequential Scan）は、テーブル全体を順次スキャンすることを意味します。

### 問題15: C
**解説:** パーティショニングは特定期間のクエリには有効ですが、全期間にわたる集計では複数パーティションをスキャンする必要があり、必ずしも高速化されません。

### 問題16: B
**解説:** 統計情報が古いと、オプティマイザが非効率な実行計画を選択する可能性があります。

### 問題17: C
**解説:** 非正規化の主な目的は、JOINを減らしてクエリのパフォーマンスを向上させることです。

### 問題18: C
**解説:** CHECK制約は、列の値が指定した条件を満たすことを保証します。

### 問題19: C
**解説:** ビューは仮想的なテーブルであり、実際にはストレージ容量を削減しません。

### 問題20: C
**解説:** JSONBはバイナリ形式で格納され、インデックス作成が可能で、検索が高速です。

### 問題21: B
**解説:** このクエリは組織の階層構造を再帰的に展開し、各従業員の階層レベルを計算します。

### 問題22: B
**解説:** 過去3日間（現在行を含む）の移動平均は、ROWS BETWEEN 2 PRECEDING AND CURRENT ROWで表現されます。

### 問題23: B
**解説:** トリガー関数内では、OLDで更新前の値、NEWで更新後の値を参照します。

### 問題24: B
**解説:** SELECT FOR UPDATEは、選択した行に対して排他ロックを取得し、他のトランザクションからの更新を防ぎます。

### 問題25: C
**解説:** 各行ごとにCOMMITすることは、トランザクションのオーバーヘッドが大きく、パフォーマンスを悪化させます。

### 問題26: B
**解説:** 注文時の商品情報は変更される可能性があるため、注文時点の情報をJSONで保持するのが適切です。

### 問題27: B
**解説:** 監査ログの最も重要な目的は、変更履歴を完全に記録することです。

### 問題28: C
**解説:** 分散データベースでは、2相コミット（Two-Phase Commit）プロトコルが使用されます。

### 問題29: B
**解説:** 全てのクエリをストアドプロシージャ化することは、必ずしもセキュリティ強化にならず、開発効率を下げる場合があります。

### 問題30: B
**解説:** 大量データ、リアルタイム分析、高可用性の要件を満たすには、パーティショニングとレプリケーションの活用が最も重要です。
