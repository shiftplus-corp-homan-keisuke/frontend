# Session 1: コンポーネント、インスタンス、要素

## 学習目標

このセッションでは、React の最も基本的かつ重要な概念である「コンポーネント」「インスタンス」「React 要素」の違いを学びます。これらを理解することで、React が内部でどのように動作するかの基盤が築かれます。

- **コンポーネント**と**コンポーネントインスタンス**の違い
- **React 要素**とは何か
- JSX が `React.createElement` に変換される仕組み
- なぜコンポーネント関数を「直接呼ぶ」べきではないのか

## コンポーネントとは

コンポーネントは、UIの一部を記述するために書く**通常の JavaScript 関数**です。この関数は**React 要素（Element Tree）を返します**。通常、JSX 構文を使ってこれらの要素を記述します。

```jsx
function Greeting({ name }) {
  return <h1>Hello, {name}!</h1>;
}
```

コンポーネントは**設計図（Blueprint）**のようなものです。家の設計図から実際の家が何軒も建てられるように、1つのコンポーネントから複数の**インスタンス**が生成されます。

## コンポーネントインスタンスとは

React は、コードの中でコンポーネントを使用するたびに、そのコンポーネントの**インスタンス**を作成します。

```jsx
function App() {
  return (
    <>
      <Greeting name="Alice" />
      <Greeting name="Bob" />
      <Greeting name="Charlie" />
    </>
  );
}
```

上記の例では、`Greeting` コンポーネントは1回だけ定義されていますが、3つの**インスタンス**が作成されます。

各インスタンスは：
- **独自の Props** を持ちます（Alice, Bob, Charlie）。
- **独自の State** を持つことができます。
- **独自のライフサイクル**を持ちます（誕生 → 生存 → 消滅）。

> **重要**: コンポーネント＝設計図、インスタンス＝実際に存在する実体

## React 要素とは

React がコンポーネントインスタンスを処理（レンダリング）すると、その結果として **React 要素** が生成されます。JSX は内部的に `React.createElement()` 関数呼び出しに変換され、その結果が React 要素です。

```jsx
// JSX
<h1 className="title">Hello</h1>

// 内部的に以下に変換される
React.createElement('h1', { className: 'title' }, 'Hello')
```

React 要素は、単なる**不変の JavaScript オブジェクト**です。

```javascript
// React 要素のイメージ（簡略化）
{
  type: 'h1',
  props: {
    className: 'title',
    children: 'Hello'
  }
}
```

この React 要素が最終的に**実際の DOM 要素**に変換され、ブラウザ上に表示されます。

**流れのまとめ**:
```
コンポーネント (設計図)
    ↓ 使用されるたびに
コンポーネントインスタンス (Props, State, ライフサイクルを持つ)
    ↓ レンダリングされると
React 要素 (JavaScript オブジェクト)
    ↓ Commit フェーズで
DOM 要素 (ブラウザ上に表示)
```

## なぜコンポーネント関数を直接呼んではいけないのか

以下のような書き方を見たことがあるかもしれません。

```jsx
// ❌ 悪い例：関数を直接呼び出す
function App() {
  return (
    <div>
      {TabContent({ item: content[0] })}
    </div>
  );
}
```

一見動作するように見えますが、React はこれを**コンポーネントインスタンス**として認識しません。

### 問題点

1. **コンポーネントツリーに現れない**: React DevTools で確認すると、`TabContent` がツリーに存在しません。
2. **State が親コンポーネントに漏れる**: 直接呼び出したコンポーネント内の `useState` などのフックが、親コンポーネントの State として扱われてしまいます。
3. **フックのルール違反**: 複数回呼び出すとフックの順序が崩れ、エラーが発生する可能性があります。

### 正しい方法

```jsx
// ✅ 正しい例：JSX としてレンダリング
function App() {
  return (
    <div>
      <TabContent item={content[0]} />
    </div>
  );
}
```

こうすることで、React は `TabContent` を正しくコンポーネントインスタンスとして認識し、適切に処理します。

## まとめ

| 用語 | 説明 |
|------|------|
| **コンポーネント** | UI の設計図。関数として定義される。 |
| **インスタンス** | コンポーネントの実体。Props, State, ライフサイクルを持つ。 |
| **React 要素** | `React.createElement` の結果。DOM 更新の情報を持つ JS オブジェクト。 |
| **DOM 要素** | 最終的にブラウザに描画される HTML 要素。 |
